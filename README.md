# stat2rmarkdown

Shared core utilities for the **2Rmarkdown** family of R packages, which convert the
analysis files of point-and-click statistics software into reproducible R Markdown reports:

| Converter | Input | Public repository |
|-----------|-------|-------------------|
| `spss2rmarkdown` | SPSS `.sps` syntax + `.sav` data | <https://github.com/giladfeldman/spss2rmarkdown> |
| `jamovi2rmarkdown` | jamovi `.omv` analysis files | <https://github.com/giladfeldman/jamovi2rmarkdown> |
| `jasp2rmarkdown` | JASP `.jasp` analysis files | <https://github.com/giladfeldman/jasp2rmarkdown> |
| `stata2rmarkdown` | Stata `.do` syntax + `.dta` data | <https://github.com/giladfeldman/stata2rmarkdown> |

`stat2rmarkdown` holds the pieces every converter needs: assembling an R Markdown document
(YAML header, setup chunk, inline stylesheet, session-info footer), rendering statistical
tables as HTML, quoting variable names and a few small helpers.

**How the converters use it.** The four converters do **not** currently import this package:
each carries its own copy of the equivalent helpers, and `render_jmv_tables()` here is the
reference implementation their copies are kept in step with. Install `stat2rmarkdown` if you
are writing a converter of your own, or want the same report skeleton in your own code —
installing it does not change the behaviour of the four converters.

Version 0.1.1 · MIT licence · R >= 4.1.0

## Installation

```r
# install.packages("remotes")
remotes::install_github("giladfeldman/stat2rmarkdown")
```

Imports: `glue`, `stringr`, `knitr`. Suggests: `testthat`, `broom`, `modelsummary`.

## Quickstart

Build a complete, knittable R Markdown document from the skeleton functions:

```r
library(stat2rmarkdown)

rmd <- paste(
  generate_yaml_header("Mini report", author = "Generated by stat2rmarkdown"),
  generate_style_block(),
  generate_setup_chunk(packages = "stats"),
  "# Analysis\n",
  "```{r model, results='asis'}",
  "fit <- lm(mpg ~ wt, data = mtcars)",
  "stat2rmarkdown::render_model_table(fit)",
  "```\n",
  generate_session_footer(tool_name = "stat2rmarkdown",
                          repo_url = "https://github.com/giladfeldman/stat2rmarkdown"),
  sep = "\n"
)
out <- file.path(tempdir(), "mini-report.Rmd")
writeLines(rmd, out)
cat(readLines(out, n = 6), sep = "\n")

quote_var("income (USD)")   # "`income (USD)`"
safe_as_numeric(c("1.5", "oops"))   # 1.5 NA
```

Knit the result with `rmarkdown::render(out)` (needs `rmarkdown` and pandoc).

## Function reference

Every exported function has a help page (`?function_name`).

### Document assembly

| Function | Returns | What it does |
|----------|---------|--------------|
| `generate_yaml_header(title, author = "Generated by stat2rmarkdown", date = <inline R date>, theme = "lumen")` | character(1) | YAML front matter for `html_document`: floating table of contents (depth 4), `code_folding: hide`, `self_contained: true`, `df_print: paged`, `highlight: tango`. `title` must be a single string. |
| `generate_style_block()` | character(1) | An inline `<style>` block (font stack, spacing, styling for tables of class `s2r-table` and `pre` output). Put it straight after the YAML header; `self_contained: true` keeps it in the single HTML file. |
| `generate_setup_chunk(packages = c("haven", "dplyr", "tidyr", "ggplot2", "stringr"), options = list(), extra_code = NULL)` | character(1) | A `setup` chunk (`include=FALSE`) that sets `knitr::opts_chunk` and calls `library()` for each package. Defaults: `echo = TRUE`, `message = FALSE`, `warning = FALSE`, `error = TRUE`, `fig.width = 10`, `fig.height = 7`; `options` overrides any of them. `extra_code` is appended after the `library()` calls. |
| `generate_session_footer(tool_name = "stat2rmarkdown", repo_url = ...)` | character(1) | A closing "Session Info" section with a `sessionInfo()` chunk and a credit line linking `tool_name` to `repo_url`. **Pass `repo_url` explicitly** — see Limitations. |

### Rendering results as HTML tables

Both functions `cat()` HTML and return `invisible(NULL)`; call them from a chunk with
`results='asis'`.

| Function | What it does |
|----------|--------------|
| `render_jmv_tables(x, heading_level = 4)` | Walks a `jmv` results object (from `jmv::ttestIS()`, `jmv::ANOVA()`, `jmv::descriptives()`, ...) and writes each table as an HTML `<table class="s2r-table">`, parsed from the table's own `asString()` layout. Tables `jmv` marks `visible = FALSE` (structural tables for options that were not requested) are skipped. A table whose layout cannot be parsed is written as a verbatim code block instead of being dropped. Recurses into groups and arrays up to 8 levels deep. A plain data frame is written with `knitr::kable()`. |
| `render_model_table(model)` | Writes a fitted model (`lm`, `glm`, `fixest`, `lmer`, ...) as an HTML coefficient table. Tries, in order: `modelsummary::msummary(output = "html")` if `modelsummary` is installed; `broom::tidy()` + `knitr::kable()` if `broom` is installed; otherwise `print(summary(model))` as plain text. |

### Utilities

| Function | What it does |
|----------|--------------|
| `%\|\|%` (`x %\|\|% y`) | Null-coalescing: `x` unless it is `NULL`, then `y`. |
| `quote_var(var)` | Wraps a single variable name in backticks if it contains anything other than letters, digits, `_` or `.`, or starts with a digit; otherwise returns it unchanged. |
| `validate_vars(data, vars, case_sensitive = FALSE)` | Stops with `Variables not found in data: ...` if any of `vars` is not a column of `data`; returns `invisible(TRUE)` otherwise. Case-insensitive by default (SPSS upper-cases names, Stata is case-preserving). |
| `safe_as_numeric(x)` | Converts haven-labelled vectors, factors (through their labels, `as.numeric(as.character(x))`) and character vectors (non-numeric strings become `NA`, without a warning) to numeric; numeric input is returned unchanged. |
| `create_output_dir(base_name, output_root = "output")` | Creates `output_root/YYYY-MM-DD-HH-MM-SS-<base_name>` (characters outside `[A-Za-z0-9_-]` in `base_name` become `_`) and returns its path. |
| `log_message(msg, level = "INFO")` | Prints `[YYYY-MM-DD HH:MM:SS] LEVEL: msg`. `level` must be one of `"INFO"`, `"WARN"`, `"ERROR"`. |

## Output format

Every generator returns a single character string of R Markdown, so the pieces can be joined
with `paste(..., sep = "\n")` and written with `writeLines()`. The HTML table renderers write
to standard output, which is what `knitr` captures in a `results='asis'` chunk.

## Configuration

The package reads no environment variables and no `options()`.

## Limitations and failure modes

- **`generate_session_footer()`'s default `repo_url` does not point at this repository**, so a
  report built with the default gets a credit link readers cannot open. Always pass
  `repo_url` (the Quickstart shows how).
- `render_jmv_tables()` rebuilds tables from `jmv`'s plain-text layout. Columns are split on
  runs of two or more spaces, so a cell that itself contains two consecutive spaces would be
  split in two.
- `render_model_table()`'s output depends on which optional packages are installed
  (`modelsummary`, then `broom`, then plain text), so the same model can render differently on
  two machines.
- R 4.4.0 and later ship their own `%||%` in base R with the same meaning; attaching
  `stat2rmarkdown` masks it and R prints a "masked from 'package:base'" note.
- `create_output_dir()` has one-second resolution: two calls with the same `base_name` in the
  same second return the same directory.

## Keeping this README honest

`tools/check_docs_coverage.R` derives the public surface from the package source (every
`export()` in `NAMESPACE`, every environment variable and option the code reads) and fails if
any of it is missing from this README, if `DESCRIPTION`, `NEWS.md` and `CITATION.cff`
disagree on the version, or if the Quickstart above does not run:

```sh
Rscript tools/check_docs_coverage.R            # run from the package root
Rscript tools/check_docs_coverage.R --no-run   # skip executing the Quickstart
```

`tests/testthat/test-docs-coverage.R` pins it both ways (a planted undocumented export must
fail, the real package must pass) when the tests are run from a source checkout.
